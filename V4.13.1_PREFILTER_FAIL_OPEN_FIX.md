# Forex Scanner v4.13.1 — Prefilter cold-start / scanner freeze fix

Problem found in v4.13:
The new Adaptive Prefilter ran before the normal scanner loop and could call
`bootstrapLocalHistory()` for all Session Top-8 pairs. Each bootstrap requests
up to 1500 1M candles. On a cold start this means up to eight sequential REST
bootstraps before the scanner reaches the normal Top-5 analysis, which can make
the scanner appear frozen and can trigger API throttling.

Fix:
- Prefilter no longer performs REST bootstrap.
- Prefilter uses existing LOCAL 1M history only.
- If local history is not ready, the pair gets a session-based fail-open ranking.
- The normal scanner loop bootstraps only the selected Top-5 pairs.
- FVG Birth Tracker runs in Prefilter only when local history already exists.
- Existing Score/Entry/Confirmation/TOO LATE logic is unchanged.

Expected behavior:
- First scan starts promptly and selects Top-5 using session fallback where needed.
- Those Top-5 are bootstrapped by the normal scanner.
- Later scans become increasingly adaptive as local history becomes available.
