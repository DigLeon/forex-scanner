# v5.0.6 — API Economy v2

Goal: reduce Twelve Data REST credit usage while WebSocket is unavailable, without changing scoring, Entry Engine, Expiration Engine, Signal Lifecycle, or TRADE rules.

Changes:
- One shared REST updater owns recurring `time_series` refreshes.
- Default updater tick: one symbol every 12 seconds (~5 scheduled refreshes/min maximum).
- Initial history remains 1500 x 1m candles; recurring refresh is only 5 candles.
- Full Scan only bootstraps when local history is cold/insufficient; it no longer refreshes already-ready history.
- Candidate Discovery uses local history only and makes zero direct REST calls.
- Fast Recheck uses local history + shared REST price snapshot and makes zero direct REST calls.
- Expired signal checks use the shared snapshot and make zero direct REST calls.
- Outcome Engine was activated from the previous escaped/commented block and now samples 3/5/10/15/30m outcomes from shared/local data with zero direct REST calls.
- `/api/auto-scan` exposes `apiEconomy` status.
- Existing REST Credit Manager remains the final 7/min safety gate.
- Daily API usage counter remains enabled.

Environment:
`SHARED_REST_UPDATER_TICK_MS=12000`
`REST_INCREMENTAL_CANDLES=5`

Expected steady-state recurring REST usage for five active pairs: approximately 5 `time_series` requests/minute, with cache/coalescing potentially reducing actual outbound calls. On-demand `/api/price` requests from the GUI/API can still consume an additional credit.
