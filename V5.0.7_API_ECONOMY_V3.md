# v5.0.7 — API Economy V3

Fixes a regression introduced by the incremental REST updater.

## Fixed

- Incremental 1M REST refreshes no longer replace the 1500-candle local history.
- Existing local history is merged with the newest REST candles by datetime and remains capped at 1600 candles.
- Completed WebSocket candles, when available, are merged after REST.
- Shared REST Updater now naturally reports `INCREMENTAL` after bootstrap because local history remains populated.
- Candidate Discovery priority scans are deduplicated by `pair + latest closed 1M candle` in addition to the existing cooldown.
- Auto Scan can keep using local history and should no longer fall into `Not enough closed candles` after the first incremental refresh.

## Expected log pattern

After startup:

```text
[LOCAL HISTORY] EUR/USD REST BOOTSTRAP
[LOCAL HISTORY] EUR/USD READY ~1500 candles | REST source: API
```

Later:

```text
[LOCAL HISTORY] EUR/USD REST INCREMENTAL
[LOCAL HISTORY] EUR/USD READY ~1500-1600 candles | REST source: API/CACHE
[SHARED REST UPDATER] EUR/USD | INCREMENTAL | next tick: 12s
```

The important invariant is that `READY` must stay above 100 candles after incremental refreshes.
