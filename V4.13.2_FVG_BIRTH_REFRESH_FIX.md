# v4.13.2 — FVG Birth post-refresh fix

## Root cause
In v4.13.1 the FVG Birth Tracker was called in the Adaptive Prefilter before
the normal scanner's REST bootstrap/resync.

When Twelve Data WebSocket is disconnected, local history can be stale at that
moment. The full scanner then refreshes the selected Top-5 pair and sees a new
closed candle / new FVG, but Birth Tracker was not called again. This explains
cases where Entry Zone History first sees a fresh FVG already as MISSED while
no `[FVG BIRTH]` line appeared.

## Fix
- Keep the lightweight prefilter birth scan for already-local history.
- Run `scanFvgBirths(symbol, closedCandles)` again immediately AFTER the
  selected pair's bootstrap/resync and BEFORE full analysis.
- Structural deterministic Zone IDs prevent duplicate births.
- Console now prints one detailed `[FVG BIRTH]` line per newly discovered FVG:
  ID, direction, timeframe, formation time, first-seen time and Best price.
- Birth records now include `detectedAfterFormationSeconds` to measure how late
  the scanner first observed the structural FVG.
- No Score, Entry Zone, TOO LATE, Candle Confirmation, decision, or Telegram
  thresholds were changed.

This is an observability/timing fix only.
