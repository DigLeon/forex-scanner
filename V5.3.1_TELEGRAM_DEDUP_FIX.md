# v5.3.1 Telegram Duplicate Fix

## Fixed

- Removed duplicate Telegram chat IDs at startup using `Set`.
- Added atomic in-flight deduplication for GET_READY/PREPARE alerts.
- Added atomic in-flight deduplication for TRADE alerts.
- GET_READY dedupe now prefers stable `setupId`, then FVG id, then symbol/direction/expiration fallback.
- A GET_READY alert and a later real TRADE remain separate allowed events.
- Scanner analysis, scoring, expiration, statistics and signal logging are unchanged.

## Root cause

Fast Recheck and Full Scan can reach `sendEarlyAlert()` concurrently. Previously the dedupe key was stored only after the asynchronous Telegram request completed. Two concurrent calls could both pass the initial `Set.has()` check and send duplicate messages. The key is now reserved before the network await.
