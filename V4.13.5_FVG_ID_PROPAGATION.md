# v4.13.5 — Canonical FVG ID propagation

The canonical FVG ID is now created at the structural source and carried
through the full analysis pipeline:

detectImbalances
→ FVG.fvgId
→ multi-timeframe SMC
→ selected imbalance
→ Entry Zone.fvgId
→ Entry Zone Lifecycle.fvgId
→ Entry Zone History

Entry Zone History now uses the propagated `fvgId` directly. It only falls
back to structural/fuzzy ID generation when no physical FVG ID is available
(for example REFERENCE / ATR fallback zones).

FVG Birth Tracker also consumes the same source-generated `fvgId`.

No Score weights/floors, Entry Zone boundaries, TOO LATE rules, Candle
Confirmation, decision logic, or alert behavior were changed.
