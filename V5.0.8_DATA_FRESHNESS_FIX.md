# v5.0.8 — Data Freshness Fix

Changes are intentionally limited to market-data freshness and duplicate priority scans.

- Shared REST updater now follows the latest dynamic full-scan universe instead of polling both the static session list and dynamic scan list.
- Newly rotated scan pairs therefore continue receiving incremental 1M refreshes after their initial bootstrap.
- `candleData.newestClosedCandle` and `newestClosedAgeSeconds` now come from the freshest merged closed candle actually passed to analysis, not potentially older REST snapshot metadata.
- Candidate Discovery dedupe now also knows which closed 1M candle was already processed by any full-pipeline scan, so it will not request another priority scan for the same pair + same closed candle.
- No scoring, entry-zone, expiration, Telegram, TRADE, or WAIT > 60 research rules were changed.
