# v5.3 — Targeted Freshness Rescue

Purpose: recover a potentially actionable signal when the only timing problem is stale market candles, without turning freshness into a blanket REST refresh.

Behavior:
- Rescue is considered only when the candidate score is already >= the effective required score.
- Entry must already be BEST ENTRY, GOOD ENTRY, or ACCEPTABLE.
- The analysis must be stale (`Market candle data is stale` or signal age > 120s).
- One forced incremental Twelve Data 1m refresh is allowed for that symbol/closed-1m candle.
- The refreshed candles and price are merged into local history and the full analysis is run again before the normal TRADE/WAIT/SKIP execution gate.
- Weak, late, BAD ENTRY, TOO LATE, and below-threshold candidates do not spend a rescue REST request.
- Same symbol + same closed 1m candle is deduped so repeated priority/full scans cannot keep force-refreshing it.
- Forced rescue bypasses only the normal fresh-cache shortcut. If Twelve Data fails, the existing stale-cache fallback remains intact.

Unchanged:
- scoring model and thresholds
- entry-zone calculations
- expiration engine
- Telegram score filter
- WAIT > 60 / TRADE statistics
- shared REST updater cadence
- v5.2 session-off API guard
